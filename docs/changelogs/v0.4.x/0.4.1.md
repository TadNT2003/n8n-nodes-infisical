# Changelog — 0.4.1

_Compared against 0.4.0._

This release expands the **Infisical** node beyond Secrets and Folders into full lifecycle management of **Environments**, **Projects**, **Secret Imports**, and **Secret Tags**, and adds two safety controls to **InfisicalSync**'s Infisical → n8n operations: OAuth credential handling and an update strategy that preserves OAuth tokens.

## Highlights

- **New `Environment` resource** — Create, Get, Get by Slug, Update, Delete, Restore.
- **`Project` resource gains write operations** — Create, Update, Delete (alongside the existing read operations).
- **New `Secret Import` resource** — Create, List, Update, Delete.
- **New `Secret Tag` resource** — Create, Get, Get by Slug, List, Update, Delete.
- **InfisicalSync — "OAuth Credential Handling"** option on Auto Sync, so re-syncing never silently wipes a connected OAuth credential's access token.
- **InfisicalSync — "Update Strategy"** option using n8n's `isPartialData` to merge updates and preserve fields the sync doesn't manage (notably OAuth tokens).

## Infisical node — new resources & operations

### Environment (new resource)

| Operation | Method | API endpoint |
| --- | --- | --- |
| Create | `POST` | `/v1/projects/{projectId}/environments` |
| Get | `GET` | `/v1/projects/{projectId}/environments/{id}` |
| Get by Slug | `GET` | `/v1/projects/{projectId}/environments/slug/{envSlug}` |
| Update | `PATCH` | `/v1/projects/{projectId}/environments/{id}` |
| Delete | `DELETE` | `/v1/projects/{projectId}/environments/{id}` |
| Restore | `POST` | `/v1/projects/{projectId}/environments/{id}/restore` |

> **Version note:** **Get by Slug** and **Restore** (plus the **Hard Delete** toggle's soft-delete behavior) rely on newer Infisical API features. Older self-hosted instances only expose get-by-ID and treat every delete as permanent; on those instances these operations return an error — use **Get** (by ID) instead.

### Project — new write operations

| Operation | Method | API endpoint |
| --- | --- | --- |
| Create | `POST` | `/v1/projects` |
| Update | `PATCH` | `/v1/projects/{id}` |
| Delete | `DELETE` | `/v1/projects/{id}` |

Create supports description, slug, KMS key, template, project type (Secret Manager / Cert Manager / KMS / SSH / Secret Scanning / PAM / AI), default-environment creation, and delete protection. Update covers name, description, slug, auto-capitalization, delete protection, secret sharing, and PIT version limit.

### Secret Import (new resource)

| Operation | Method | API endpoint |

Create links a source environment/path into a destination environment/path, with optional cross-project source (`sourceProjectId`) and replication (`isReplication`).

## InfisicalSync — Infisical → n8n safety controls

### OAuth Credential Handling (Auto Sync from Infisical)

OAuth1/OAuth2 credentials obtain their access token through an interactive browser consent, stored by n8n in an `oauthTokenData` field that is not synced. Because updating a credential can overwrite its stored data, a new **OAuth Credential Handling** option controls how Auto Sync treats OAuth types:

- **Create Only** (default) — create OAuth credentials that don't exist yet, but never update existing ones, so a connected credential's token is never overwritten. You still authorize each newly created OAuth credential once in n8n.
- **Skip** — never create or update OAuth credentials; report them as skipped for manual handling.
- **Update All** — treat OAuth credentials like any other credential.

OAuth types are detected by n8n type name (`*OAuth2Api` / `*OAuth1Api` / `oAuth2Api` / `oAuth1Api`); non-OAuth credentials are unaffected.

### Update Strategy (Sync from / Auto Sync from Infisical)

Controls how existing n8n credentials are updated. Both strategies send a complete, schema-valid payload (n8n validates `data` against the full credential schema before applying it); the difference is what happens to fields the sync doesn't track:

- **Partial Merge** (default) — sets `isPartialData: true` so n8n **merges** the payload into the existing credential. Fields n8n manages but Infisical does not — notably **OAuth access tokens** (`oauthTokenData`) — are preserved instead of wiped. Requires a recent n8n version that supports partial credential updates.
- **Full Replace** — overwrites the entire credential data object. Use for older n8n versions that don't support partial updates. Wipes fields not included in the sync, including OAuth access tokens (the credential must be re-authorized).

`syncFromInfisical` now also builds a complete, schema-valid payload for updates (previously it sent raw folder data), fixing update failures for credential types whose schema requires fields the folder doesn't store.

## Compatibility notes

- **Infisical:** Environment **Get by Slug** / **Restore** and the **Hard Delete** soft-delete behavior require a recent Infisical version. Older self-hosted instances return errors for those.
- **n8n:** Updating an existing credential over the public API — used by both Update Strategy modes — requires a recent n8n version that supports credential updates (and, for **Partial Merge**, the `isPartialData` flag). On older n8n, updates may be unavailable.
